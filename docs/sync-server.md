# 数据同步使用说明

本版保留自建服务器、云端网盘和 iCloud Drive 三个入口。当前已实现自建服务器；网盘和 iCloud 的双向文件同步尚未实现，页面明确显示开发状态。

## 连接步骤

1. 双击项目根目录的 `启动贾维斯测试版.cmd`。
2. 左侧独立的「数据同步」→「自建服务器」。原生设置中的「同步」也可进入该页面。
3. 填写兼容贾维斯六表接口的服务器地址与设备令牌。使用原贾维斯服务时，沿用其同步 API 地址与设备令牌。请在应用中填写令牌，不要发到聊天或写进交付文档。
4. 点击「检查连接并预览」。此步骤只读服务器，显示两边的笔记本、笔记、来源、待办、灵感和关联数量，不上传本机记录。
5. 有相同 ID 的不同内容时，选择保留服务器内容或使用本机内容。相同名称、不同 ID 的记录分别保留；最多展示 100 项冲突，计数包含全部。
6. 核对地址、范围与冲突处理，勾选确认，再点击「确认合并并启用同步」。连接前自动保存本机两库备份；成功后由服务器统一保存六表记录，其他设备的独有记录也会显示在此电脑。

更改地址或令牌会清除页面预览。预览后两边任一数据版本变化，确认会被拒绝，须重新预览。预览十分钟有效。已连接的资料库可以核对原服务器连接，连接其他服务器需使用独立资料库。

## 同步范围与恢复

| 内容 | 当前行为 |
|---|---|
| 笔记本、笔记、来源、待办、灵感、关联 | 通过服务器双向共享，保留原字符串 ID |
| AI 会话归档、重要标记与学习回顾进度 | 仅保存在本机 |
| 附件文件、循环提醒规则、桌面设置 | 仅保存在本机；共享正文可包含附件占位 |
| 模型密钥、微信认证和设备令牌 | 保存在本机 Windows 凭据管理器，不进入业务快照 |

来源与笔记中的正文会上传，服务器管理员可读取。HTTPS 保护传输，本版未实现六表数据端到端加密。

后台约每五秒刷新一次。断网新建进入待同步箱，已有记录编辑失败时保留草稿。并发冲突须核对草稿后重试。页面显示待同步、待核对、最近成功同步时间与实际错误；只有服务确认后才显示成功。

首次同步若提交响应丢失，任务、原本机快照及固定请求身份已落盘，凭据单独保存。重启后先查询回执；确认未提交时才重发同一请求。结果未明期间的新保存进入本机草稿，确认连接后可核对重试。令牌失效时在原任务中补充新令牌并「恢复连接并核对回执」，不创建第二次导入。

确定拒绝的首次合并会保留本地模式与原内容，可重新预览。本机备份位于资料目录 `backups/server-*`；核心还保留不含凭据的 `server-backup-*` 快照。不会把本机库文件直接放入网盘。

## 服务器接口

地址填写源站，例如 `https://你的同步服务器`；本机测试可用 `http://127.0.0.1:端口`。地址不包含路径、查询参数或内嵌凭据。需要兼容已有贾维斯服务的接口：

| 请求 | 作用 |
|---|---|
| `GET /api/sync/health` | 设备认证与探活 |
| `GET /api/sync/snapshot` | 六表快照、版本及 hash |
| `POST /api/sync/command` | 带 expected、fingerprint、requestId 的业务命令，含原子 import 合并 |
| `GET /api/sync/receipt` | 按请求身份和指纹核对提交回执 |

认证使用 Bearer 设备令牌。页面地址须指向同步 API 的源站；只有静态网页的地址无法替代同步服务。现有 `jarvis-butler/server/api.ts` 支持该协议。本轮未改动原服务源码、端口、生产配置或真实数据；无需增加云端数据表。
