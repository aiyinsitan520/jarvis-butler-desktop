# 资料目录、会话与每日回顾

资料库采用现有六表数据库及 Markdown 投影。编辑文件通过相同的业务命令、版本检查与持久回执保存。不会用文件覆盖整个数据库，也不会自动将会话归档上传到 VPS。

新资料库将两份数据库放在 `.jarvis/`。旧预览保持原路径，在其 library 子目录生成阅读文件；迁移后采用统一目录。凭据用稳定资料库 UUID 标识，兼容原路径哈希凭据。文件夹迁移不导出密钥；换电脑需要重新配置。

笔记、待办、灵感元数据示例：

```markdown
---
id: "保留应用生成的原ID"
table: "notes"
base: "保留原校验值"
title: "可修改标题"
notebookId: "保留或改为已有笔记本ID"
tags: ["学习"]
---
可编辑的正文。
```

扫描采用30秒后台轮询及启动补扫描，主页面关闭后由托盘继续执行。格式使用 YAML 的 JSON 值子集；文字需双引号。修改错误、重复ID、未知记录和路径问题都会保留文件并报告。新记录先在应用创建；直接删除文件只产生确认事项。冲突处理先保存外部稿到 conflicts。连接服务器时草稿／未知回执继续使用原服务规则，不绕过版本校验。

附件阅读副本在 attachments，笔记使用相对链接；原始附件仍由桌面管理。`index.json` 包含笔记投影位置、笔记本、来源和关系。会话阅读版及索引在 conversations，已采集的文字版本在 conversations/raw，原始日志不被本程序修改。回顾正文可以阅读；请在对应 `.notes.md` 文件维护个人复述与练习结果，报告重生成时旧正文进入 reviews/history。

来源授权只接受明确选择的日志目录。Codex 解析 response_item 消息并兼容 event_msg；Claude Code 读取 user／assistant 消息；Gemini CLI 读取 session JSON。保留消息ID、时间及可取得的分支信息；不导入工具执行结果。截断、轮转、未写完JSON等以内容校验和持久游标处理。当前单文件20MiB、最多1000会话／24MiB归档；超限会显示错误，不能称为已导入。

自动回顾默认关闭。启用后沿用已选模型，并确认云端可见范围。每日报告最多20个来源、模型输入最多1.2万字符，摘录可能截断。每条模型结论必须引用给出的来源ID，不自动把讨论标为已掌握。不调用工具或执行会话指令。失败原文保留，重复周期不自动重试不明的模型任务；用户可手动重试。

桌面与微信分开记录状态。发送前记录 unknown；超时保留结果未知，不自动重发。缺少上下文则等待本人发送“今日回顾”。主设备设置保存在本机；两台电脑共享微信时应只启用一台推送。真实 iLink 主动发送能力需实测，不承诺离线电脑或协议限制之外的定时投递。

迁移可选择磁盘或文件夹：空目录直接使用，非空目录下以 create_dir 独占新建“贾维喵资料”，同名目录存在则拒绝覆盖。最终资料目录仍须为空且与原库互不包含；父目录可包含其他文件但不复制它们。冻结两库写入，使用 SQLite 快照、文件复制校验和 integrity_check 后原子切换启动位置并重启。失败恢复原库写入，原文件与不完整副本保留。备份含清单、两库、附件和受管理阅读目录；恢复先备份现状，在新的空目录恢复，避免覆盖现有资料。运行中的 SQLite 不支持网盘直接同步。
